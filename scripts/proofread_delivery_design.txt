Proofreading delivery recovery: requirements, not an activation procedure
===========================================================================

Current status
--------------
The central proofreading and parsing workflows are disabled. The BHA Space's
API intentionally responds 503 to new submissions by default; it does not
dispatch them. Changing BHA_PIPELINE_SUBMISSIONS_PAUSED to 0 is not approved by
this document. User drafts live in the browser's session storage and are not a
durable submission queue. A draft may be lost when its tab or session closes.

Before the pause, a GitHub repository_dispatch response of 204 could be shown
as accepted even when the matching workflow was disabled. GitHub acceptance
does not establish an Actions run, durable payload retention, archive PR,
review completion, or user-visible status. Previous accepted requests whose
events were not processed may be unrecoverable: no complete durable ledger of
their payloads has been established. Do not invent or replay missing events.

Gaps in existing implementation
--------------------------------
* The BHA duplicate-request cache is process memory, expires and can be lost on
  restart. It does not prove that an earlier accepted request was handled.
* Large payloads are stored as Git blobs prior to dispatch, but those blobs do
  not themselves form a discoverable, durable user queue or completion record.
* The current workflow has no receipt bound to request_id that the submitting
  user can query. Local mock tests do not prove remote PR/issue idempotency.
* Proofreading may affect multiple files and may auto-merge; parsing creates
  multiple PRs, may upload review crops, and updates a tracker. A timeout or
  cancellation can leave a partial outcome and must not be blindly replayed.
* The Space has a credential capable of dispatching; the current central token
  cannot read the Actions global permission. Individual workflow state alone
  does not prove all triggers, access and producer isolation are correct.

Minimum properties for a separately reviewed future implementation
-------------------------------------------------------------------
1. Define a durable, access-controlled payload record with an immutable request
   identity, content digest, source revision and deterministic duplicate rules.
   Do not log or expose submitted article content and do not depend on a Git
   blob remaining reachable without a verified retention/reference policy.
2. Distinguish locally drafted, durably queued, claimed, partially processed,
   awaiting review, merged, rejected, and failed/uncertain states. A user must
   be able to retrieve the authoritative state without treating 204 as done.
3. Define explicit idempotency and recovery for each external effect: blobs,
   branch/commit updates, both parsing PRs, tracker issue/comments, review
   crops and optional auto-merge. Require exact repository, branch, base, head,
   payload digest and run identity. Foreign or ambiguous state stops recovery.
4. Specify a durable claim and serialized writer protocol. Timeouts, process
   death, retries, duplicate dispatch and concurrent edits must never turn an
   uncertain or partially completed action into an overwrite or duplicate.
5. Prove permission/availability of the central global Actions switch and each
   exact workflow, event type, credential and repository identity; independently
   verify queued and running work. Space environment, callback and retention
   changes need their own review. Do not change unrelated workflow states.
6. Build safe end-to-end tests in isolated repositories with synthetic content,
   real event execution and service responses. Include duplicate, timeout,
   disabled workflow, stale base, malformed/segmented input, process restart,
   partial parsing PRs, concurrent edits, merge and access-denied scenarios.
   Follow with explicitly reviewed, reversible production acceptance and prove
   user-visible status before opening submissions.

These requirements are incomplete and confer no permission to enable Actions,
turn off the Space pause, create PRs, replay real submissions, reindex, run OCR,
release processing protections, change Reader routing, or collect resources.
