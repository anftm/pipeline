# 按需读取不良的 PDF 结构整理

`pdf_range_assets.py` 自动检查原始 PDF 和其他格式生成的 PDF，依据真实 PDF.js
读取量选择结构整理或线性化候选。实现和运行方式见 `pdf_range_workflow.md`。
`qpdf --object-streams=generate --stream-data=preserve` 可集中存放页面字典等小对象，
保留原始图像、字体和内容流。产物通过独立评测 manifest 与共享 sidecar 原子发布，
原件下载地址继续可用。

2026-09-14 检查的 Teachers 源版本为
`1d03396c8365f9ad57e9dc316a1838991c862ac0`。
`A4 毛泽东主席/01-01 毛泽东全集/17  1942.05-1943.04.30.pdf`
（阅读 ID `24zevoo78ulnw`）为 86,815,965 字节、539 页、147 个目录条目。
539 个顶层 `/Page` 对象散布在 77 个 1 MiB 块中；PDF.js 6.3.289
初始化检查页面树时就读取 80,524,509 字节。线上冷浏览器复现同样的字节量，
Range 返回 206 正常。不能将这个现象归因于服务器没有支持 Range。

同一源文件、qpdf 10.6.3、真实 PDF.js 6.3.289 的本地读取实验：

| 变体 | 分块 | 首页累计字节 | 目录解析后累计字节 | 中间页后累计字节 |
| --- | ---: | ---: | ---: | ---: |
| 原件 | 1 MiB | 80,524,509 | 80,524,509 | 80,524,509 |
| 原件 | 256 KiB | 63,485,149 | 63,485,149 | 63,485,149 |
| 对象流整理 | 1 MiB | 1,702,610 | 2,751,186 | 3,799,762 |
| 对象流整理 | 256 KiB | 1,178,322 | 1,440,466 | 1,964,754 |

整理后文件为 86,637,266 字节；优化来自对象布局，而非降低图像质量。
保持 Reader 的 1 MiB 配置即可大幅降低首屏读取量。以上为 PDF 字节量，
不包含引擎、字体资源或首次 HTTP 探测，不等同于用户网络上的加载耗时。
首页、中间页、末页的实际渲染像素和提取文本在原件和整理版之间一致；
空闲时读取量没有增加。

完整 HF Reader 的本地 HTTP Range 验收（相同引擎、1 MiB 分块）还会渲染
首屏附近页面：打开后累计读取 3,799,762 字节、4 次 Range 请求，首次探测
另发送 65,536 字节；空闲不继续下载。跳到第 10、270、539 页后累计读取
6,945,490 字节、7 次 Range 请求，均成功显示且无页面异常。
539 页的内容流、资源树（包含 542 个不同的原始流）、MediaBox/CropBox、
旋转设置、元数据及全部目录目标已逐项比较一致。这是本地候选产物验收，
线上仍需在发布后通过原阅读 ID 单独检查。

不要直接全库启用、根据文件大小自动归类，或将线性化等同于按需读取优化。
新增来源前必须检查首页、目录、跳页和空闲时的读取量，并验证页数、全部页面
内容/资源、页面几何、目录目标和实际渲染。不同 PDF 对象布局可能得到不同结果。
源文件更新后也应重新进行这一验收，已有测量不证明未来版本表现。
